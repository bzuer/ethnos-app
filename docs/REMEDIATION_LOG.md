# Frontend v2 remediation log

_Archived from `CLAUDE.md` on 2026-08-03 by /doctor. Historical record of the completed P0-P3 API v2 reconciliation. The live v2 contract lives in `CLAUDE.md` (API v2 Entity Model); the pre-fix audit is [`FRONTEND_DIAGNOSIS.md`](FRONTEND_DIAGNOSIS.md)._

**⚠️ v2 reconciliation (2026-07-24).** The backend was rebuilt to **API v2.0.0** (17 domains / 78 endpoints; full chapters in `docs/api_doc/`). A complete evidence-grounded audit of the frontend against it lives in **[`docs/FRONTEND_DIAGNOSIS.md`](docs/FRONTEND_DIAGNOSIS.md)** (173 findings). Consequences that override stale claims elsewhere in this file:
- **The works/persons full-text engine is Manticore, not Sphinx.** `meta.performance.engine` / per-row `search_engine` report `"Manticore"`; the old MariaDB works FULLTEXT indexes no longer exist. Every "Sphinx" mention below (and the `search/sphinx` route + `actSearchSphinx` naming) is legacy branding to be reconciled.
- **Entire ready domains are unsurfaced:** Institutions (~410k), Subjects (~165k / 78M relations), the dedicated citation graph (`/works/{id}/citations|references|metrics|network`), Collaborations, aggregate Metrics/leaderboards, Publications list, the DOI resolver, and Signatures (~3M). No route/wrapper/action exists for these.
- **Several frontend reads are drifted** (venue `metrics{}`/`indexing{}` read at old top-level/`summary_snapshot` paths → badges blank; autocomplete reads `first_author`/`orcid`/`issn` at wrong locations; `normWork` drops authors for list rows). See the diagnosis for the file:line ledger. The per-line descriptions below document current *code intent*, not necessarily correct v2 behaviour — treat them as the rebuild backlog, not as ground truth.
- **P0 applied (2026-07-24, build + live-verified)** — the stop-the-bleeding pass landed: `fetchJson` now preserves the error envelope via an `ApiError` class (`status`/`code`/`errors`) plus `isNotFoundError`, `unwrapData`/`unwrapList`/`readPagination` helpers; the error policy is `NOT_FOUND`→`notFound()`, transient→throw (never a soft-404, never silent wrong-data substitution). `normalizeVenue` (in `src/lib/venues.ts`, applied in `getVenue`/`getVenuesPage`/`getHomeTopVenues`) flattens v2 `identifiers`/`indexing`/`metrics`/`ranking` so venue badges (DOAJ/SciELO/Scopus/OA), h-index/impact, ISSN/E-ISSN, subjects (`term`) and the LLM-justification description all render. `normWork` recovers list-row authors (`authors_preview`→`first_author.name`→`authors.author_string`). Autocomplete reads v2 nesting. Wrong-data fallbacks removed: `searchWorks` no longer degrades a filtered query to unfiltered, `actSearchSphinx` no longer masks 400s with browse rows. Work citation/reference tabs are uncapped via `WorkCitationList` + `actGetWorkCitations`/`actGetWorkReferences` (paginated `/works/{id}/citations|references`), and the bibliographic citation/reference **counts bind to the authoritative `/works/{id}/metrics`** (loaded in `loadWork`), not the stale denormalized columns. The venue-detail `loading.tsx` was removed so missing venues return a real **404** (with `force-dynamic` + `loading.tsx`, Next streamed a 200 shell before `notFound()` could set the status). Remaining diagnosis items (Institutions/Subjects/etc., the identifier registry, one shared linked result-row, OA-narrowing in `normalizeWorkDetail`) are **P1–P3**.
