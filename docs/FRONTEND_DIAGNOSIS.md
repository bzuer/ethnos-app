# Ethnos Frontend — Definitive Diagnostic Report

*Audit scope: 15 frontend surfaces + 7 API capability domains, probed live against Ethnos.app Academic Bibliography API v2.0.0 (`127.0.0.1:1211`). All file:line and endpoint evidence below is drawn from the surface/capability audits and the uniformity synthesis.*

---

## 1. Verdict & Executive Summary

**Verdict:** *Alive but under-delivering — a few surfaces render correctly while the frontend silently drops v2 fields, collapses every backend error into a hard 404, and ignores the majority of the ready API. It is a patchwork, not the definitive instrument the corpus warrants.*

The core surfaces work on their happy paths — envelopes are unwrapped, real booleans are read, the showcase/search routing in `searchWorks` is correct, and the primary search results page handles totals, chips, and pagination properly. But three structural facts dominate everything else:

1. **The app was built against a pre-v2 schema and never fully migrated**, so it reads fields the API moved or dropped and renders populated data as blank.
2. **The data core throws away the API's structured error envelope**, so recoverable failures render as permanent 404s and two code paths silently substitute *wrong* data.
3. **The frontend uses a fraction of the ready API** — entire first-class domains have no route, wrapper, or action.

### The 7 most important systemic problems

| # | Problem | Severity | Blast radius |
|---|---------|----------|--------------|
| 1 | **Stale pre-v2 field reads blank real data.** Surfaces read `summary_snapshot{}`, top-level `issn/orcid/h_index/impact_factor`, `first_author` as a string, and phantom `mag_id`. Venue h-index/impact/DOAJ/SciELO/Scopus badges *never render*; venue & work subjects sections *never render*; autocomplete shows `[object Object]`. | Critical | Venues catalog, venue detail, autocomplete, person detail, work detail, export layer |
| 2 | **Error envelope discarded → transient failures become hard 404s.** `fetchJson` keeps only a numeric status; every caller collapses to `null`/`[]`. A 503/429/400 is indistinguishable from a real `NOT_FOUND`. Two fallbacks substitute *unrelated* data (dropped filters; browse rows shown as search results). | High | Data core, all detail pages, search, home, lists |
| 3 | **Entire API domains unsurfaced.** Institutions (~410,716), Subjects (~165,779), citation/reference/metrics/network graph, Collaborations, aggregate metrics/leaderboards, DOI resolver, Publications, Signatures (~3M) — no route, wrapper, or action. | Critical | Whole app |
| 4 | **Result rows are isolated from the entity graph and discard discovery signal.** `cited_by_count` never shown; `venue.id`/`first_author.person_id` never linked; no sort UI; no citation filter. Detail pages fetch embedded analytics blocks, discard them, then re-fetch. | High | Home, search, advanced, all detail tabs |
| 5 | **Citation/reference tabs hard-capped at ≤100 with no pagination.** A 43,419-citation work shows 100 rows and no "load more"; the dedicated `/citations`, `/references`, `/metrics`, `/network` endpoints are entirely unused. | Critical | Work detail |
| 6 | **No shared boundary — the patchwork seams.** The `{status,data,pagination,meta}` envelope is unwrapped 5+ ways; OA is detected 3 incompatible ways; identifiers are rendered by 3 divergent per-page maps; pagination is handled 5+ ways; there is no single normalize-at-the-boundary adapter. | High | Every surface |
| 7 | **Stale "Sphinx" branding + an "advanced search" with no form.** The engine is **Manticore** (`meta.engine`), yet UI H1, SEO, code (`actSearchSphinx`), and robots still say Sphinx; `/search/sphinx` has *no form or filters at all* — it is an orphaned results list, not advanced search. | High (Critical on that surface) | Advanced search, i18n/SEO, robots |

## 3. Correctness Bugs

Dead fallbacks, swallowed errors, wrong pagination/ids, and hydration risks that produce wrong behavior (not just missing capability).

### High severity

- **`normWork` drops ALL authors for list-shaped works → Person-page exports emit author-less / "Unknown author" citations.** `normWork` reads authors only from a detail-style `authors[]` array; list rows carry `authors_preview[]`, `first_author.name`, or `authors.author_string`, so it returns `authors: []`. `PersonTools` feeds exactly those list items to BibTeX/RIS/JSON/APA. — `work-export.ts:99`; `PersonTools.tsx:52/66/76/87`; live `/persons/7922/works` item `authors:{total_count:2,author_string:"Victoria Clarke; Braun"}`.
- **Every error collapses to `null` → a 503/400 renders an identical hard 404.** `actGetWorkFull`/`getWork`/`getVenue` use `catch { return null }`; detail pages call `notFound()`. Combined with §2's discarded error envelope, a transient timeout mis-signals a permanent not-found to users *and* Googlebot. — `actions.ts:92-103`; `endpoints.ts:96-98`; `api.ts:105`.
- **`searchWorks` non-empty-`q` fallback silently drops every active filter.** When `/search/works` throws, the fallback issues `/works?search=…` with only `search/page/limit` — `author, venue, subject, language, year_*, open_access, peer_reviewed, type` are discarded, so a filtered query degrades to an unfiltered one with no signal. — `endpoints.ts:76-83`.
- **`actSearchSphinx` 3-level silent fallback masks validation errors and shows browse rows as results.** `/search/advanced → /search/works → /works?search=`, each wrapped in `catch {}`. A 400 from `/search/advanced` (`q<2 chars`, bad `sort_by`) surfaces generic browse rows as "advanced search results." — `actions.ts:42-58`; live `/search/advanced?q=a`→400 VALIDATION_ERROR (swallowed).
- **Bibliographic citation/reference counts are wrong and rows vanish while the tab shows data.** The table binds to the stale denormalized `work.metrics.{citation_count,reference_count}` and only renders each row when `> 0`. Work 22519667: embedded `reference_count=0` (References row **hidden**) yet `/references` returns 56 and the References tab lists 42. Work 7539537: embedded `citation_count=21,493` vs `/metrics.total_citations_received=43,419` vs Cited-by tab shows 100 — **three different numbers reach the user.** — `works/[id]/page.tsx:457-468`.

### Medium severity

- **E-ISSN silently dropped by a guard bug.** The identifiers loop runs `if (!venueIssn && (normalized==='issn' || normalized==='eissn'))`; because `issn` is processed first and sets `venueIssn`, the `eissn` branch is skipped. — `venues/[id]/page.tsx:325-330`; live `identifiers{issn:'0084-6570',eissn:'1545-4290'}` renders only the print ISSN.
- **`getVenueWorks` fallback returns cross-venue works.** `/works?venue_id=` is ignored by the API; if ever called it returns the global browse. Dead today (no callers) but a latent landmine. — `api.ts:110-138`.
- **Home fetch/render size mismatch.** Fetches 15 venues (`getHomeTopVenues(15,1)`) but JSX slices to 25; wrapper default is 25 — the ceiling never applies. — `page.tsx:80,101`; `endpoints.ts:33`.
- **`ListPageClient.formatAuthorsForDisplay` can't read the `{total_count, author_string}` shape → "Unknown author."** Object branch checks only `name/full_name/preferred_name`. — `ListPageClient.tsx:52-57`.
- **Export swallow-and-substitute.** `fetchWork` returns `null` on any error and the mapper falls back to the possibly-months-old localStorage snapshot with no notice; no distinction between a 404 (removed/merged id) and a transient failure. — `ListPageClient.tsx:72-90`.
- **Author affiliation reads fields v2 never provides.** `affRaw.department/organization/institution/unit` + `mag_id`; v2 affiliation is `{id,name,type,country,_links}` only. — `works/[id]/page.tsx:209,307-315`.

### Dead branches & hydration

- **`WorkRelatedList` reads `cited_by_count`/`references_count` that citation/reference items never carry** → those meta bits are always absent. — `WorkRelatedList.tsx:36-37,77-88`.
- **`normalizeWorkDetail` inconsistent identifiers shape (CONFIRMED)**: scalar `doi` at root alongside array-valued `identifiers.doi`; `work-detail.ts:166` then reads `identifiers.isbn` expecting a scalar but gets an array. — `works.ts:372`.
- **Root OA narrowing (PLAUSIBLE)**: `normalizeWorkDetail` collapses the API's *any-publication* root `open_access`/`peer_reviewed` to the *primary* publication's own flags, so a work whose secondary edition is OA can lose its OA badge/link. — `works.ts:331-338`.
- **`startPrompt` empty-state unreachable**: no-param search routes to `/works/showcase` which always returns ~20 rows, so the "start prompt" copy never renders. — `SearchResultsClient.tsx:128,212-217`.
- **`useSearchParams()` in a `force-static` route with no `<Suspense>`** on the advanced-search surface, against the app's own documented pattern (the primary results client gates on a `mounted` flag; this one doesn't). — `search/sphinx/page.tsx:8`; `SearchSphinxClient.tsx:25`.
- **`getVenue` not memoized** → `/venues/{id}` fetched twice per request (metadata + render); plus 3 extra `/works` fetches for tabs the embedded payload already contains. — `venues/[id]/page.tsx:167,241,247,255,263`.

## 5. Structural Non-Uniformity

The frontend is a set of independently-authored surfaces with no shared boundary. The same six concerns are each re-solved several ways.

### The patchwork seams → the pattern to adopt

| Seam | Divergent variants in the tree | Unify to |
|---|---|---|
| **Envelope unwrap** | `data ?? work ?? res` (correct); `data \|\| results \|\| items` (`endpoints.ts:16,39`, `actions.ts:81`); `results ?? data ?? items ?? res` (`api.ts:118`); a **6-shape probe** (`SearchSphinxClient.tsx:189-194`); and a multi-shape **producer** `actSearchSphinx` that emits `{data:{results,facets}}` OR `{data:[…]}` (`actions.ts:42-58`) | Unwrap **once** inside `fetchJson`; return a typed `{data, pagination, meta}` tuple. `.results`/`.items` never appear on the v2 envelope — delete them. |
| **Pagination** | Trust server booleans (correct: results, venues); OR server boolean with re-derived heuristics ignoring `pagination_total_exact` (`SearchSphinxClient.tsx:210-211`); offset math (`endpoints.ts:173`); **fictional cursor** (`api.ts:110-138`); client oversample×4 + dedup on a **stale one-row-per-authorship** assumption (`endpoints.ts:219-234`); embedded ≤100 cap with no load-more; limit-clamp split-brain | One `paginate()` helper trusting `hasNext/hasPrev/total` + reading `pagination_total_exact`; clamp `limit` in exactly one place; wire the nested list endpoints so no tab is silently capped. |
| **Error handling** | `fetchJson` discards `{code,message,errors[]}`; blanket `catch→null` (detail) and `catch→[]` (home); silent multi-level fallback to **wrong** data; `meta.page_degraded/engine/performance` never read | Preserve the typed error on the thrown `Error`; one shared policy: `NOT_FOUND→notFound()`, transient→explicit error UI (never a 404, never silent substitution), truly-empty→one shared empty-state. |
| **OA detection** | File-based SSOT `buildFileOpenAccessUrl` (correct); ~12-alias legacy probe + string coercion (`works.ts:74-104`); DOI-only third-party `oadoi.org/{doi}` that renders a **dead badge when no DOI** even if `open_access=true` (`WorkMetaBadges.tsx:92,146-154`); wrong-path `summary_snapshot` read (`VenuesList.tsx:157`) | One resolver: `file_summary.best_oa_url → files[].best_oa_url → openacess_id → (last) DOI resolver`; one `isOpenAccess()` reading the real boolean. |
| **Identifier rendering** | Link-less shared formatter (`GroupedIdentifiers.tsx:1-19`); works page inline map that **drops OpenAlex** and labels unknowns with raw `key.toUpperCase()` ("SCIELO_PID" untranslated); a **second** map on venue detail (no scielo, E-ISSN bug); hand-written `<tr>` rows on person detail (Lattes plain text); catalog reads only issn/eissn | Promote `GroupedIdentifiers` into an **identifier registry**: family key → localized label + canonical href builder. Works/venues/persons/exports all consume it. |
| **Empty states** | Silent frozen-empty on home; two-branch copy with one unreachable branch; redirect-away on sphinx; real copy on person/venue lists; `null→hard 404`; two **dead soft-404 relics** (`SearchNotice`, `VenuesNotice`) that contradict the 404 policy | One shared empty-state component; delete the soft-404 relics. |

### The three deeper structural failures

1. **No single normalization boundary.** v2 flattening lives in `works.ts` but is applied inconsistently: `endpoints.ts` `getWork` **duplicates** the `loadWork` pipeline (and is dead), pages re-flatten inline (`WorkMetaBadges.toSavedItem`, works/[id] identifiers), and the flatten is **incomplete for list rows** (`normWork` returns `[]` authors). → *Make normalization one mandatory layer at the fetch boundary emitting one canonical shape covering both detail and list rows.*
2. **Rows disconnected from the entity graph.** `cited_by_count`, `venue.id`, `first_author.person_id` arrive on every row and are shown/linked nowhere; there is no shared result-row component. → *One shared, linked result-row reused on Home/Search/Advanced/tabs.*
3. **The same enum/model re-encoded in multiple places** (12-value `work_type` split between `SearchForm` (7 shown) and the exporter type maps (different omissions)). → *Define each enum/model once and drive every consumer from it.*

## 7. Prioritized Roadmap

Framed as diagnosis — *what must be fixed/built*, ordered so the frontend stops being a patchwork and becomes the definitive instrument.

### P0 — Stop the bleeding: correctness, data-blanking drift, and the core boundary

1. **Introduce one typed v2 entity model + a single normalize-at-the-boundary adapter** (Work/Publication/Venue/Person, covering *both* detail and list rows). Ban ad-hoc field reads. This is the keystone that makes the other fixes local.
2. **Unwrap the envelope once in `fetchJson`** and **preserve the error envelope** (`code`/`message`/`errors[]`). Give every caller one policy: `NOT_FOUND→notFound()`, transient (TIMEOUT/RATE_LIMITED/VALIDATION/INTERNAL)→explicit error UI — **never a hard 404, never silent substitution**.
3. **Kill the wrong-data fallbacks**: `searchWorks` non-empty-`q` fallback dropping all filters; `actSearchSphinx` masking validation errors with browse rows.
4. **Fix the data-blanking drift** (visible today): VenuesList → read `metrics{}`/`indexing{}` (drop `summary_snapshot`); venue detail → subjects `term`, E-ISSN guard, SEO ISSN from `identifiers{}`; autocomplete → `first_author.name`, `identifiers.orcid`, `identifiers.issn`.
5. **Restore `normWork` authors for list rows** (`authors_preview` → `first_author.name` → `author_string`), unbreaking Person-page exports.
6. **Uncap Citations/References**: back the tabs with `/works/{id}/citations` (+ `type` filter) and `/works/{id}/references` (resolved + unresolved + counts), paginated.
7. **Bind the citation/reference *counts* to the authoritative `/works/{id}/metrics`**, not the stale denormalized `work.metrics.*`.
8. **Wire affiliations to institution links** (zero new fetch — `affiliation.id`/`_links.self` already present) and add the **person-page name-signature disambiguation link**.

### P1 — Close the biggest capability gaps and unify

1. **One shared, linked result-row component** (title+subtitle, linked `venue.id`, linked `first_author.person_id`, `cited_by_count`, `type`, OA) reused on Home/Search/Advanced/entity tabs.

## 8. Recommended CLAUDE.md Corrections

The diagnosis proves the following statements in `CLAUDE.md` stale or wrong. Bringing the doc current is part of the rebuild's foundation.

- **"Sphinx is the primary engine with a MariaDB fallback"** — **Wrong. The engine is Manticore.** `meta.engine="Manticore"` on `/search/works` and `/search/advanced`; the old MariaDB works FULLTEXT indexes no longer exist. Every Sphinx reference must change: the `/search/works` engine claim, *"`getHomeRecentWorks` is Sphinx-independent by design,"* *"Sphinx may legitimately be off during a deploy,"* and the `actSearchSphinx` naming.
- **"prefer reading `primary_publication` and merging scalar identifier aliases from it"** — Misleading. **`primary_publication` carries no `identifiers` object** (always undefined); you read `primary_publication.doi` (a scalar publication field), never a `primary.identifiers` merge. The doc should also specify **one canonical flat identifiers shape** — the current `normalizeWorkDetail` returns array-valued `identifiers.doi` *and* scalar top-level `doi` in the same object (`works.ts:372`), which `work-detail.ts:166` then mis-reads.
- **`normalizeWorkDetail` "preserves root-level `open_access`/`peer_reviewed` when the primary lacks them"** — Understates a bug. The code actually **narrows** the API's *any-publication* root flags to the primary publication's own boolean (`works.ts:331-338`), inverting the documented "true if ANY publication is OA/peer-reviewed" semantics. Document the correct precedence (root first).
- **"`/persons/{id}/works` returns one row per authorship record (an author listed twice appears twice), so `getPersonsWorks`/`getPersonsWorksProminent` dedupe by work id; the latter oversamples `limit × 4`"** — **Stale.** Live: 100/100 unique rows, 0 dupes, `pagination.total = works_count`. The endpoint no longer duplicates authorship rows, so the dedupe is a no-op and the 4× oversample is pure waste.
- **"the metrics row binds to `work.metrics.{citation_count,reference_count,download_count,view_count}`"** — These are **stale denormalized columns** (embedded `citation_count=21,493` vs authoritative `43,419`; `reference_count=0` while `/references` returns 56). The doc should point at the dedicated **`GET /works/{id}/metrics`** endpoint as authoritative — which it currently never mentions.
- **Key Files present `getWork`/`getPublication` (in `endpoints.ts`) as the canonical work/publication wrappers** — they are **dead code** with no callers; the live work-detail path is `loadWork()` in `work-detail.ts`, which duplicates the same fetch/unwrap/normalize pipeline. Reconcile to a single path (or delete the wrappers).
- **`pickPrimaryPublication` described as the live fallback heuristic** — effectively **unreachable for `/works/{id}`**, which always returns `primary_publication` (and list items have no `publications[]`). Note it as legacy/no-op for detail.
- **External-identifier-links rule ("Detail pages must render outward links … OpenAlex → `https://openalex.org/{id}`")** — silently **unmet on the work detail page**, which explicitly drops OpenAlex (`works/[id]/page.tsx:221`). Either the rule or the code must be reconciled — flag it so the rebuild honors the rule uniformly via the identifier registry.
- **Project Layout / Key Files omit the entire ready API surface** — there is no acknowledgement that **Institutions, Subjects, Citations-network, Collaborations, aggregate Metrics, Publications, the DOI resolver, and Signatures** are unbuilt. The doc should record these as known gaps so the patchwork is visible rather than implied-complete.
- **(Adjacent) messages/privacy copy references an "API proxy" data flow** — contradicts CLAUDE.md's own "there is no in-app HTTP proxy" architecture rule; the stale SEO copy in `messages/*.json:441` should be corrected to the server-action flow.
